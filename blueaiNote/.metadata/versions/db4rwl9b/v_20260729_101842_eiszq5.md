## 摘要

本文记录了广告投放系统的元数据建模、字典引用机制与 ADK Agent 工具设计，并附有开发测试及业务投放样例。

- 以 `tbl_api_metadata` 统一管理各媒体平台的 API 字段路径、中文展示名、业务同义词、数据类型、字段层级、必填/常用/默认/启用状态，以及叉乘配置。
- 大型字典通过 `is_reference` 与 `allowed_values` 指向独立底表；后端直接使用国家代码、受众 ID 等物理值写入选项和单元格，避免额外的中文转换。
- `query_api_metadata` 是 `ads_agent` 的核心字段对齐工具：启动时加载当前媒体的常用字段，遇到长尾需求时再加载全量字段或按关键词检索；切换媒体时需清理上一媒体的字段状态。
- 附录包含 Claude Agent 沙箱测试、GCS 文件上传命令，以及 Google/TikTok 广告创建和跨媒体 Media Plan 的需求示例。
- 核心目标是将字段 Schema 从 System Prompt 中抽离，改由运行时状态和检索工具动态提供，以降低提示词负担并提升字段匹配及配置扩展能力。

### 2.1 统一字段与元数据配置表（`tbl_api_metadata`）

该表用于定义常用字段、中文别名、展示逻辑、大列表引用关系以及业务同义词：

- **api_field_path**（主键，文本）：对应媒体 API 的物理参数路径，全局唯一。例如 `campaign.shopping_setting.merchant_id` 或 `campaign.name`。
- **media**（文本）：区分广告平台。例如 `google` / `tiktok` / `meta`。
- **display_name**（文本）：多维表上展示给业务用户的中文列头名。例如 `谷歌商户ID`。
- **desc**（文本）：业务大白话描述，用于 AI 将用户的模糊表述对齐到物理字段。例如 `商户ID, 商家ID, Merchant ID, Feed账号`。
- **data_type**（文本）：字段在 API 中的物理数据类型（`string` / `number` / `single_select` / `multi_select`）。**特别注意：引用（Reference）不作为独立的物理类型，大列表字典在底层全部作为单选或多选类型处理**。
- **is_reference**（布尔/复选框）：**是否引用外部表。当设为 true 时，表示该字段引用了外部字典底表。**
- **allowed_values**（JSON/文本）：
  - 当 `is_reference == false` 时，存储的是死硬 of 物理枚举数组（如 `["TARGET_CPA", "MAXIMIZE_CONVERSIONS"]`）；
  - **当 is_reference == true 时，存储的则是引用的目标字典底表名**（如 `"tbl_countries"`）。
- **field_level**（文本）：**字段所属层级。选填：campaign（广告系列层级）或 ad（广告/广告组层级）。**
- **is_cross**（布尔）：**是否叉乘字段。如果为 true，代表该列输入的多个值，在下发部署时，需要依次和其它被设置为 true of 叉乘字段的值，进行笛卡尔积排列组合（叉乘），自动构建生成所有的 ad group and ad 组合。**
- **is_mandatory**（布尔）：媒体平台物理创建 of 必选项。
- **is_common**（布尔）：常用属性。勾选后默认作为常用 properties 注入给 Agent。
- **is_default**（布尔）：默认展示。勾选后，多维表初始化时默认展示为一列。
- **is_active**（布尔）：“仅增不删，弃用打标”。当 API 废弃该字段时设为 `false`，确保历史配置表可追溯，Agent 仅读取 `true` 的行。

### 2.2 字典引用数据源底表（如 `tbl_reference_countries` 等）

对于国家、地理位置、受众包等长尾和大数据量字典，当主表的 `is_reference == true` 时，其具体值（Value）指向独立的外部底表（表内字段包含：`key`、`api_id` 等，如 `US`）：

- **后端写入与填充机制**：后端向用户确认的多维表写入数据时，**完全不需要进行任何 display_name 中文转换，直接提取引用底表中的物理 Value 码（如 US、GB 或具体的物理受众 ID）填充至该列 of 选项数组（Options）并直接写入单元格即可**。由于业务用户对这些物理代码（如国家代码 US、受众包 ID）本身就有直观认知、完全看得懂，因此去掉一切繁琐 of 中转翻译。这使得单元格填充极其轻量、扁平。

## 3. ADK 工具集定义与 Agent 关系

在 ADK (Agent Development Kit) 框架中， we 新增并改造以下核心工具，供不同的 Agent 动态调用。

### 3.1 字段与元数据加载检索工具：`query_api_metadata`

- **定义与作用**：**这是直接供 ads_agent 调用的终极数据对齐工具。ADK 系统中，我们将所有的 properties 状态和 Schema** **提示词****段落，从 Agent 的 System** **Prompt** **中彻底抽离。这些数据直接常驻存储于 ADK runtime 的 State中。**
- **工具入参规范**：
  - `platform` (string, 必填): 对应当前媒体（`google` / `tiktok` / `meta`）。
  - `query_type` (string, 必填): **加载的数据范围模式：**
    - `"common"`: **加载常用字段数据**。返回由系统直接将 `is_common == true` &amp; `is_active == true` 的元数据转换合并后的标准 JSON Schema 字典，供 Agent 快速理解最基本/常用字段。
    - `"all"` / `"long_tail"`: **加载全部/长尾字段数据**。当 Agent 发现用户在大白话需求中提到了非常用、生僻的长尾诉求，或者需要进行非常规匹配时，传此参数，一次性加载当前平台全部活跃字段元数据，进行自适应对齐。
  - `search_query` (string, 选填): 如果提供了关键字，工具将专门对 API 元数据中的物理路径、同义词 and 中文别名进行快速子检索过滤，精简返回结果。
- **工具调用决策**：
  - **初次唤醒**：`ads_agent` 启动时，必须首先主动调用一次 `query_api_metadata(platform="meta", query_type="common")`，将常用字段载入上下文，用于初版草稿及默认多维表渲染。
  - **长尾触发**：只有当 Agent 深度解析用户请求，发现有长尾配置时，才按需触发调用 `query_api_metadata(platform="meta", query_type="all")` 进行全局比对。
  - **更新机制：**state中仅记录单一媒体的字段，当请求其他媒体的字段时，需要清空上一个媒体（一般是创建完成一个媒体的广告后，继续创建下一个媒体的广告时）
